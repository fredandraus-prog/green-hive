# Internationalization

GH-0701 turns `@green-hive/i18n` from a scaffold into the small, shared presentation contract used
by the Reference App. It intentionally has no React, browser, HTTP, database, session or provider
dependency.

## Supported interface locales

The Reference App currently supports `pt-BR` (the default) and `en-US`. `resolveLocale()` accepts
only those canonical locales or their `pt`/`en` language families and otherwise falls back to
`pt-BR`. A stored legacy or malformed preference therefore cannot break a screen.

`preferredLocale`, `preferredLanguage` and timezone are user presentation preferences. They never
select an app, workspace, tenant, platform role or authorization path. Those values continue to be
derived only from the verified session and protected server boundaries.

## Reference App behavior

- Before sign-in, the browser's preferred locale selects the initial interface locale safely.
- After sign-in, the verified account profile's persisted `preferredLocale` replaces that initial
  choice; changing the Profile language saves through the existing protected account route and
  updates the view immediately.
- The document `lang` attribute follows the resolved locale. Date/time formatting uses `Intl` with
  a safe fallback, so an invalid timezone cannot crash the interface.
- Message interpolation returns plain text. React continues to escape output; translations are not
  HTML templates and the package has no remote translation loading.

This checkpoint does not add third-party translation APIs, automated translation, locale-specific
authorization, number/currency policy, or a public language-management API. Additional application
copy and future product locales must be added deliberately with matching typed dictionaries and
tests.
